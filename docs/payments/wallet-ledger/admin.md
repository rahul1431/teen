# Wallet Ledger — Admin

Two tabs on the Finance page (`admin-panel/src/pages/Finance.tsx`) give admins a direct view over the raw ledger; both are `finance`-role gated backend-side (`services/admin-service/src/index.ts`), with no client-side role hiding — a non-`finance` admin sees the tabs and controls and only hits 403s on action.

- **Ledger tab** (`GET /api/admin/finance/ledger`) — the whole platform's `wallet_transactions` table, filterable by type/wallet/user, paginated 50/page. This is a read-only window onto exactly the rows `WalletService.credit`/`debit`/etc. write — useful for tracing any single idempotency key or user's full history, but it's raw: no join back to what caused the transaction beyond `reference_id`/`description`, and no indicator of whether a `game_debit` was a lock, consume, or direct debit (see `wallet-ledger/frontend.md` for the same ambiguity on the mobile side).
- **Reconciliation tab** (`GET /api/admin/finance/reconciliation?days=`) — daily `payment_orders` totals by type+status, a GGR (platform-fee/rake) trend, and totals by gateway, capped at 90 days. This aggregates `payment_orders`, not `wallet_transactions` directly — so it reflects deposit/withdrawal order status, not the underlying ledger rows those orders eventually produce. It will not surface money that's stuck mid-ledger (e.g. a `locked_balance` never consumed), since that scenario never touches `payment_orders` at all — that specific gap is now handled separately by `game-gateway`'s automatic reconcile sweep (fixed 2026-07-28, see `docs/backend-services/game-gateway/backend.md`), not this view.

There is no admin view anywhere that cross-checks `SUM(wallets.real_balance + bonus_balance + locked_balance)` against `SUM(wallet_transactions)` net or against `payment_orders` totals — reconciliation here is manual, by reading the Ledger tab's raw rows, not an automated integrity check.
