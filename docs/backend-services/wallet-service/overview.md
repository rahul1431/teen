# Wallet Service — Overview

Owns the money ledger: `wallets` (per-user real/bonus/locked balances), `wallet_transactions` (append-only ledger rows), `payment_orders` (deposit/withdrawal requests, Razorpay or manual), `payment_methods` (admin-configured UPI/bank/QR deposit destinations), and `promo_codes`/`promo_code_usages`. Kept as its own PM2 process — separate from `core-api-service` and `game-gateway` — specifically so the financial critical path can be deployed, restarted, and reasoned about independently of gameplay/matchmaking code (`ecosystem.config.js:35`: "Wallet: critical financial service, keep isolated").

The whole service is two files: `services/wallet-service/src/index.ts` (640 lines — every Fastify route, Razorpay client setup, multipart deposit-screenshot upload) and `services/wallet-service/src/wallet.service.ts` (the `WalletService` class — the only place that does row-locked, idempotent balance mutation: `credit`, `debit`, `lockForGame`, `unlockFunds`, `consumeLockedFunds`, `getBalance`, `getTransactions`). No `plugins/`, `routes/`, or `helpers/` split — unlike `core-api-service`, everything lives in `index.ts`.

**Stack**: Fastify 4, `pg` (raw SQL via a single `Pool`, no ORM/query builder), Zod for request validation, `@fastify/jwt` (player auth), `@fastify/multipart` (8MB cap, deposit proof screenshots), `@fastify/helmet`/`@fastify/cors`, `razorpay` SDK. `ioredis` is a listed dependency in `package.json` but is never imported anywhere in `src/` — dead dependency, this service does not touch Redis at all (no session/lock/cache usage).

**Deploy**: PM2 process name `teen-wallet` (`ecosystem.config.js:36-46`), 1 instance, fork mode, 200M memory cap, `env_file` = `services/wallet-service/.env`. Required env vars (`services/wallet-service/.env.example`): `PORT` (3003), `DATABASE_URL`, `JWT_SECRET`, `INTERNAL_SERVICE_KEY`, optionally `RAZORPAY_KEY_ID`/`RAZORPAY_KEY_SECRET` (Razorpay client is only constructed if `RAZORPAY_KEY_ID` is set — `src/index.ts:80-85` — online-gateway routes 503 without it). `REDIS_URL` is present in `.env.example` but unused. `MIN_DEPOSIT_AMOUNT`/`MAX_DEPOSIT_AMOUNT`/`MIN_WITHDRAWAL_AMOUNT`/`MAX_WITHDRAWAL_AMOUNT`/`PLATFORM_RAKE_PERCENT` are also present but never read — see `docs/Bugs/wallet-service-deposit-withdrawal-limit-env-vars-are-dead-config.md`. `UPLOAD_DIR` (default `/opt/teen/uploads/deposits`) is where deposit screenshots land; nginx serves them back out at `/uploads/`.

**Who calls it** (full route surface in `docs/backend-services/wallet-service/backend.md`):
- The Flutter mobile app calls it **directly** over the public internet, via nginx (`infra/nginx/game.myonlinejoker.com.conf:29-34`, `location /api/wallet/` → rewrites to `/wallet/*` → `wallet_backend` upstream on `127.0.0.1:3003`), for balance, transaction/game history, deposit methods, promo validation, manual deposit submission, and withdrawal requests. See `docs/backend-services/wallet-service/frontend.md`.
- `game-gateway` calls the `/internal/wallet/*` endpoints server-to-server (lock/unlock/consume/settle-game/credit/debit) for game stakes, wins, and dealer tips, authenticated with the shared `INTERNAL_SERVICE_KEY` header (`x-internal-key`). Not all of game-gateway's ledger writes go through these endpoints, though — `room:tip` and `autoRefillBots` in `services/game-gateway/src/index.ts` and `matchmaking.ts` write directly to the `wallets`/`wallet_transactions` tables, bypassing `WalletService` entirely (see backend.md for `room:tip`'s idempotency-key fix, 2026-07-28).
- `admin-service` calls `/wallet/deposit/manual`, `/wallet/debit/manual`, and the `/internal/wallet/*` endpoints on behalf of Finance-role admins (manual credit/debit, withdrawal approve/reject state machine, deposit reconciliation). For *reads*, `admin-service` queries `wallets`/`wallet_transactions`/`payment_orders` directly rather than calling wallet-service — see `docs/backend-services/wallet-service/admin.md`.
- `core-api-service` calls `/internal/wallet/credit` for the daily-login bonus (`services/core-api-service/src/plugins/users.ts:151-156`).
- `churn-service` calls `/internal/wallet/credit` to pay out win-back bonuses (`services/churn-service/src/churn-scorer.ts:226`) — note its fallback `walletServiceUrl` default is `http://localhost:3002`, the wrong port (wallet-service is 3003); this only matters if `WALLET_SERVICE_URL` is unset in that service's env.
- `wallet-service` itself calls out to Razorpay's API (order creation) and verifies client-submitted payment signatures via HMAC-SHA256 (no server-side webhook handling in this file — verification is client-driven, see backend.md).

`/internal/*` routes are blocked at the nginx layer for the public internet (`infra/nginx/game.myonlinejoker.com.conf:150-153`, `location /internal/ { deny all; }`), so `INTERNAL_SERVICE_KEY` is a defense-in-depth second layer, not the only one — but the header check itself fails closed on both a missing env var and a missing/wrong header (`authenticateInternal`, `src/index.ts:98-102`).
